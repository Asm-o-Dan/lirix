# Security policy

## Supported versions

Security fixes target the latest stable release published in [GitHub Releases](https://github.com/Asm-o-Dan/lirix/releases). Older releases do not have a separate security backport commitment. Development branches and preview builds may contain unreviewed changes.

## Reporting a vulnerability

Email **[dgandapas1@gmail.com](mailto:dgandapas1@gmail.com)** with the subject `Lirix security report`. Do not publish a vulnerability, exploit, credentials or sensitive logs in a public issue or pull request.

Include:

- The affected Lirix version, operating system and component.
- A description of the security impact and any required permissions or access.
- Minimal reproduction steps or a proof of concept using synthetic data.
- Relevant sanitized logs, and whether the issue has already been disclosed elsewhere.

Useful areas to report include unauthorized access to local data, unintended disclosure through notifications or overlays, unsafe handling of provider content, and device pairing or transport vulnerabilities.

The maintainer will assess the report and coordinate a fix and disclosure with you. This is a volunteer project: there is no guaranteed response or remediation deadline and no paid bug bounty program. If you receive no reply, follow up through the same private email channel.

Test only on devices and accounts you control or have permission to test. Avoid accessing another person's library or disrupting third-party lyrics providers. Share the minimum information needed to reproduce the issue.

For ordinary bugs and feature requests, use [GitHub Issues](https://github.com/Asm-o-Dan/lirix/issues/new/choose).

# Teach Mode: автоматическое правило сайта, динамические сайты, предзагрузка следующего трека — 2026-11-14

Запросы владельца (13–14.11): пользователь выделяет текст как сейчас, а привязка сайта к постоянному рабочему правилу идёт автоматически; предусмотреть динамические сайты; не тратить ресурсы; затем — предзагрузка следующего трека с учётом того, что плееры разные и очереди может не быть.

Уровень 2 (безопасность, приватность, фоновая работа). Ничего не закоммичено. На устройстве не проверялось.

## 1. Автоматическое правило после привязки

Было: после «Сохранить для песни» сайт запоминался только через отдельный диалог с шаблоном поиска и селектором ссылок.

Стало: привязка сохраняется как раньше и ни от чего не зависит (AGENTS 7.3). Сразу после неё в фоне (экран уже закрыт) `TeachAutoRule`:
1. Берёт выделенный блок как селектор содержимого.
2. Ищет шаблон поиска: сначала из переходов пользователя по сайту (`SearchTemplateDetector`), затем из поисковых форм открытой страницы (`SearchFormDetector`: только GET, только свой домен и HTTPS, без форм входа и подписки). Шаблон не выдумывается.
3. Запускает настоящий движок правил от исполнителя и названия трека (до 3 попыток).
4. Включает правило только если движок сам пришёл к тому же тексту, что выделил пользователь (совпадение слов ≥ 70 %). Иначе — черновик, который каскад не исполняет (AGENTS 7.4).
5. Уже имеющееся правило сайта того же типа обновляется на месте при успехе и не трогается при неудаче (AGENTS 7.1).

Пользователь видит одно сообщение: сайт запомнен / запомнен как сайт на скриптах / что мешает (нет поиска, песня не найдена, сайт не отвечает). Ручной диалог правила остался запасным путём.

Файлы: `ui/TeachAutoRule.kt` (новый), `ui/TeachModeScreen.kt`, `ui/TeachModeLogic.kt`, строки `strings_teach.xml` (ru/en).

## 2. Динамические сайты

Изменение решения от 10.11 («правило, работающее только через WebView, включить нельзя»): теперь такое правило включается и помечается `render: { engine: "WEBVIEW", timeoutMs }`; автоматический каскад выполняет его через скрытую отрисовку страницы.

Ожидание — не фиксированная пауза и не время до клика пользователя. Страница опрашивается каждые 300 мс и считается готовой, когда под селектором правила есть текст и его длина перестала меняться. Срок ожидания измеряется автоматической проверкой (сколько потребовалось странице) и записывается с запасом: `2 × измеренное + 1,5 с`, в границах 4–20 с. Сколько пользователь держал Teach Mode открытым, на это не влияет.

Ограничение расходов (`RuleRenderBudget`, `RuleWebViewRenderer`):
- обычные правила WebView не создают вообще;
- отрисовка только после неудачи обычного запроса и только одна за раз на всё приложение;
- не больше 6 фоновых отрисовок за 10 минут;
- сайт, не ответивший 3 раза подряд, отключается от отрисовки на час;
- в режиме энергосбережения фоновая отрисовка не выполняется;
- открытая страница Teach Mode ставится на паузу, когда приложение свёрнуто.

Безопасность скрытой страницы не менялась: нет JS-моста, нет доступа к файлам, картинки не грузятся, переходы только по домену правила и HTTPS, уничтожение по завершении и при отмене. Импортированные правила по-прежнему проверяются без отрисовки и остаются черновиками, если сайт динамический.

Файлы: `feature/lyrics/CustomRuleLyricsProvider.kt`, `ui/RuleWebViewRenderer.kt`, `LirixApp.kt`.

## 3. Предзагрузка следующего трека

Способ «переключить на следующий и обратно» отвергнут: слышимый сбой, ложные прослушивания в истории, вмешательство в чужой плеер.

Сделано: чтение очереди, которую плеер публикует сам (`MediaController.queue` и `activeQueueItemId`), без какого-либо управления воспроизведением (`PlayerQueue`):
- есть очередь и номер текущего элемента — берётся следующий;
- очередь без номера — текущий элемент ищется по названию и исполнителю, только при единственном совпадении;
- очереди нет, трек последний, следующий — тот же трек — предзагрузки нет, поведение как раньше.

Результат поиска хранится в памяти (`NextTrackWarmCache`: до 4 записей, 30 минут) и в библиотеку не пишется: у песни, которая ещё не играла, строки в базе не появляется. Когда трек начинает играть, обычный автоматический поиск берёт сохранённый результат и в сеть не ходит. Источник, отклонённый пользователем для этого трека, не используется; совпадение только при согласии исполнителя.

Предзагрузка не выполняется: без сети и в режиме «только офлайн», для неопознаваемых треков («09 / Unknown Artist»), для чёрного списка (голосовые, подкасты), если у трека уже есть текст, и при быстром пролистывании (задержка 4 с, новая заявка отменяет старую).

Файлы: `feature/lyrics/NextTrackPrefetch.kt` (новый), `feature/lyrics/AutomaticLookupCoordinator.kt`, `feature/MusicFeatureEngine.kt`, `ingestion/MediaSessionCollector.kt`, `shared/.../storage/MusicDao.kt` (один запрос, схема не менялась).

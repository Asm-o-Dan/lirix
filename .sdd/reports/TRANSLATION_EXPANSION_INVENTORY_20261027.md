## RU→EN: currently possible in principle, not yet demonstrated

HEAD `SongTranslationProviders.findLanguage(..., "en", ...)` routes to `LyricsTranslateProvider.find`. This is independent of source language: it takes title, artist and target language, but does not store a verified original language (`SongTranslation.kt:13-18`) or use a source-language query parameter (`LyricsTranslateProvider.kt:48-65`). Thus do **not** claim all RU→EN fails or succeeds; no positive live result on a Russian original was checked in this inventory.

`LyricsTranslateProvider.kt:30-41,68-81` requires exact normalized song+artist matching on search results and again on document; `TranslationMetadata.kt:14-26,28-35` normalizes diacritics/case/spacing but never converts Cyrillic↔Latin. If player reports `Кино` but source reports `Kino`, keys differ and the exact filter rejects the otherwise plausible candidate; same issue for translated/transliterated title. This is a **source-based conditional failure**, not a verified observation of a particular live page or a reason to auto-accept approximate matches. Title-only fallback :70-75 still applies the same artist identity filter. Cyrillic artist metadata also cannot use Amalgama bucket, restricted to ASCII/digits (`TranslationMetadata.kt:44-45`; `AmalgamaTranslationProvider.kt:87-91`), but Amalgama is ru-target only.

`LyricsTranslateParser.kt:19-42` verifies *target* language through the page heading, canonical host/URL, identity, translated body and attribution, and represents original and translation as independent blocks `aligned=false`; it never guarantees line pairing. A new parser must prove source/target language and identity using trustworthy page metadata, not infer original language from target, user UI language, title script or transliteration. On aliases/ambiguous editions return candidates for user selection; reject wrong requested language, unsafe URL, missing original/translation, and unsupported/changed page formats rather than silently accept. Preserve source/translator URL and display independent text where no alignment.

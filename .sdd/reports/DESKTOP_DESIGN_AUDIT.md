# Desktop: аудит интерфейса и сценариев

Дата: 17 октября 2026. Статус: source audit; визуальная приёмка не пройдена.

## Основание и границы

Прочитан полностью `.agents/skills/ui-ux-designer-pro/SKILL.md`. Применены проверка иерархии, доступности, состояния действий и согласованности. Мобильные thumb-zone/haptic, принудительный Obsidian/neon и высокий уровень анимации не перенесены на ПК: приложение сохраняет существующие шесть тем.

Свежих изображений ПК нет: захват окна у координатора повторно завершался тайм-аутом. Найденные `verify_poco_*.png` относятся к телефону и не доказывают качество текущей ПК-сборки. Ниже все находки основаны на исходниках; геометрические риски требуют проверки реального окна. Работа караоке подтверждена пользователем, это не визуальная приёмка остальных экранов.

Пути в доказательствах относительно корня проекта; номера строк на момент аудита. Продуктовый код, тесты и сборки этим аудитом не изменялись.

## Приоритеты

### P1 D-01 — правки теряются при обычной навигации

Доказательство: `desktop/src/main/kotlin/com/lirix/app/desktop/ui/DesktopFeatureDialogs.kt:31,55,85,95,136`: системный крестик и «Отмена/Закрыть» напрямую вызывают dismiss для редактора и Tap-to-Sync. `DesktopWorkspace.kt:195–197`: черновик заметки существует только в `remember(picked.trackKey, picked.userNotes)`; смена трека или уход со страницы пересоздаёт состояние. Поле аккордов заполняется асинхронно (`DesktopFeatureDialogs.kt:63`), хотя редактирование уже доступно.

Последствие: потеря набранного текста/разметки/заметок без объяснения; поздняя загрузка аккордов может затереть введённое значение. Это подтверждённые ветви исходников, не наблюдение на экране.

Исправление: единый dirty-state на черновик, явное сохранение/отбрасывание/возврат к правкам при закрытии и смене сущности. На время начальной загрузки аккордов запретить изменение или не перезаписывать уже изменённый черновик. При ошибке сохранения окно и текст остаются доступны.

Приёмка: изменить каждый из трёх редакторов; закрыть крестиком, кнопкой и переключением выбранного трека/страницы. Во всех применимых случаях правки сохраняются либо предлагаются три понятных исхода. Чистый документ закрывается без запроса; медленная загрузка не перезаписывает ввод. Двойное сохранение не запускает параллельные операции.

### P1 D-02 — шесть тем применены к Material-компонентам не полностью, контраст недостаточен

Доказательство: `Main.kt:174–177` заполняет только primary/background/surface/onSurface Material colorScheme; container/onPrimary/error/outline остаются стандартными. `DesktopFeatureDialogs.kt:31–32` создаёт отдельное окно; наследование полной темы отдельным окном надо подтвердить. `shared/src/commonMain/kotlin/com/lirix/app/ui/theme/ColorPalettes.kt` содержит textMuted, используемый как полезный мелкий текст в `DesktopWorkspace.kt:174,183,230`, `DesktopDeckScreen.kt:560`, HUD footer.

Расчёт WCAG для непрозрачных token foreground/surfaceCard (sRGB, без предположений о рендере): Spotify textMuted 3.23:1; Yandex 2.87:1; Obsidian 2.63:1; Pastel 2.16:1; Graphite 2.81:1; Paper 2.34:1. Pastel accentPrimary/surfaceCard — 2.38:1, а accent используется для текстовых заголовков/достижений/активной строки. Это ниже 4.5:1 для обычного текста; изменение opacity дополнительно требует проверки на реальном фоне.

Исправление: desktop Material mapping всех реально используемых ролей, контрастный foreground для важных подписей и выбранных/невыбранных вкладок. Не менять характер палитр целиком. Для статусных точек допускается существующий цвет при обязательном текстовом состоянии.

Приёмка: шесть тем × main/editor/source/help/poster/HUD; кнопки, поля, меню, focus, selection и ошибки соответствуют выбранной теме. Полезный обычный текст ≥4.5:1, крупный ≥3:1; disabled и декоративные элементы отмечены отдельно. Светлые темы проверены наравне с тёмными. Native file picker сохраняет платформенное оформление — его не нужно превращать в кастомную имитацию.

### P1 D-03 — компоновка не учитывает минимальное окно и масштаб Windows

Доказательство: `Main.kt:155` minimumSize задан AWT Dimension(980,680), то есть физические размеры нельзя автоматически считать dp. `DesktopWorkspace.kt:84` sidebar172dp; `DesktopDeckScreen.kt:193` left360dp; `DesktopWorkspace.kt:103` toolbar — один Row без переноса; `DesktopDeckScreen.kt:328–345` четыре равновесные вкладки в оставшейся части. `DesktopTopBar.kt:78–91` фиксированная высота44dp, левый блок с названием/источником и правый блок действий без ограничений/переноса. Медиатека использует320dp список + непереносимый ряд действий справа (`DesktopWorkspace.kt:168,190`). Диалоги открываются900×720dp (`DesktopFeatureDialogs.kt:31`) без ограничения рабочей областью.

Риск: обрезанные кнопки, сжатая область текста и действия за границами при 125–200% scaling. Сам факт обрезки пока визуально не подтверждён.

Исправление: одна desktop responsive policy по доступной ширине в dp: на узком окне компактные metadata/действия или перенос панелей; toolbar переносит элементы/имеет дополнительное меню. Dialog initial size ограничен текущей usable area, тело прокручивается, нижние действия достижимы. Не увеличивать minimumSize как единственное решение.

Приёмка: основной старт1280×820, минимальный размер, 1366×768 и1920×1080 при100/150/200%; длинный русский title/artist/source. Доступны все четыре lyric tabs, transport, Connect, редактор, Save/Cancel; элементы не перекрываются. Сравнение производится в реальном окне, не только по screenshot-тесту.

### P1 D-04 — медиатека вводит в заблуждение при фильтрации

Доказательство: `DesktopWorkspace.kt:68` picked выбирается из полного tracks; `:162–165` filtered вычисляется внутри панели отдельно; `:174` пустой поиск/фильтр получает текст про ещё не появившиеся прослушивания. «С текстом / аккордами» и «Офлайн» имеют идентичное условие plain/synced (`:163`) без chords. Выбранная справа песня может отсутствовать среди результатов.

Исправление: отличать пустую базу от отсутствия результатов; показывать активные ограничения и «Сбросить фильтры». Согласовать выбор с результатами либо явно обозначать закреплённую подробность. Определить честную семантику offline как сохранённого текста, а не аудиофайла. Поддержать chord-only cache либо убрать обещание аккордов из названия фильтра.

Приёмка: пустая база, поиск без результатов, Favorite без совпадений, artist-filter, chord-only, сохранённые LRC-only. Правый блок не выдаёт чужой результат за найденный; смена фильтра не теряет черновик заметки (D-01).

### P2 D-05 — разные входы в тему дают разное поведение

Доказательство: sidebar/settings предлагают6тем (`DesktopWorkspace.kt:94,274`), но `DesktopDeckScreen.kt:166–172` переключает любую тёмную на PAPER_INK, любую светлую на GRAPHITE_CHALK. TopBar tooltip описывает только эту пару. Нажатие не позволяет вернуться к исходной Spotify/Obsidian/Pastel теме.

Исправление: единый селектор6тем из всех входов либо запоминание последней темы каждого режима с явным названием действия. Предпочтительнее один selector, без второго несовместимого механизма.

Приёмка: из каждой темы открыть каждый вход, выбрать любую из6, перезапустить приложение; выбранная тема сохраняется и не подменяется неожиданно.

### P2 D-06 — состояние источника и сохранения недостаточно объясняется

Доказательство: `DesktopSourceDialog.kt:29–88` объединяет поиск, CSS, ручной текст, обучение правила, список правил в одном длинном потоке. Успех сохранения правила не подтверждается; generic `busy` блокирует часть кнопок, но candidate Surface остаётся кликабельным и может породить параллельные запросы. Привязка текста (`DesktopWorkspace.kt:151`) запускается без локального catch/видимого pending. Режимы blacklist показаны `.name` (`DesktopWorkspace.kt:285–286`), например CONTAINS_IGNORE_CASE вместо пользовательского объяснения.

Исправление: внутри существующего диалога раскрывать отдельно «Исправить текст этой песни» и «Настроить источник»; advancedCSS/search не обязательны для ручного ввода. Единое pending-state с disabled зависимыми действиями; подтверждение сохранения; inline error не закрывает результат. Blacklist использует русские подписи и пример regex; source package называется приложением/источником.

Приёмка: ручной текст привязывается без знания CSS; двойной клик кандидата не запускает гонку; ошибка сети/БД видна и сохраняет ввод; после сохранения правила ясно, что оно появилось в списке и к чему привязано.

### P2 D-07 — «О треке» выдаёт постоянные строки за живую диагностику

Доказательство: `DesktopDeckScreen.kt:507–508`: Discord «Активен», WinRT «Подключен» записаны как literal независимо от действительного состояния. TopBar sourceText сообщает «Играет в…» даже когда isPlaying=false; пауза отражается только цветом точки (`DesktopTopBar.kt`).

Исправление: реальные наблюдаемые статусы либо нейтральное описание возможностей без притворного успешного соединения. Пауза/остановка/ожидание отражаются текстом. Технические pipe/hook значения убрать в раскрываемые сведения; пользователю нужны источник, наличие текста, таймкоды, состояние передачи.

Приёмка: без музыки/при паузе/без Discord/при недоступном bridge UI не сообщает ложное «активен/подключен»; основной экран понятен без знания WinRT/IPC.

### P2 D-08 — итоги и постер итогов не имеют единого предпросмотра

Доказательство: `DesktopWorkspace.kt:221–248` итоги представлены линейной колонкой чисел и всех26достижений; экспорт сразу вызывает file picker и renderer (`:119–123`). Для постера трека существует preview+format+quote (`DesktopFeatureDialogs.kt:143–165`), для итогов preview нет.

Исправление: сохранить существующие данные и renderer, открыть для итогов тот же понятный flow format → section → actual preview → SavePNG. Не добавлять декоративные фиктивные графики. Достижения вынести в раскрываемый раздел или отдельный фильтр «Все/Получены»; отсутствие истории даёт один понятный next-step вместо пустых секций.

Приёмка: все5sections×2formats×6themes показывают актуальный preview, выбор до сохранения не открывает file picker, пустые данные объяснены. Экспортируемый файл совпадает с preview по содержимому/теме/формату. Сохранение заблокировано только на время операции и ошибка повторяема без потери настроек.

### P2 D-09 — подсказки и клавиатурное взаимодействие покрыты частично

Доказательство: toolbarShortcutButton содержит tooltip; F1help существует. Но `DesktopTopBar.kt` custom clickable Box для HUD/mini не имеют Button role/явной клавиши, Connecttooltip не сообщает Ctrl+Shift+D, themeIconButton не имеет hoverTooltip. `DesktopFeatureDialogs.kt:43,46` help выделяет230dp под клавиши независимо от ширины; `DesktopWorkspace.kt:75–79` shortcut matching Ctrl+1/2/3/E/T не везде исключает Shift; инпуты поиска не объявляют весь фактический поиск по lyrics.

Исправление: одно содержимое HotkeyCatalog для текста, tooltip и действия; стандартные Button/IconButton либо semantics role/state; видимый keyboardfocus. Отдельно определить поведение Ctrl+T/E во время редактирования и несовпадающих модификаторов. В справке конфликты регистрации поднять над длинным списком, дать понятный путь устранения без обещания всех клавиш.

Приёмка: Tab/ShiftTab достигает всех действий в логичном порядке; Enter/Space активируют выбранную кнопку; focus виден во всех6темах. Для горячих действий tooltip содержит title+combination. Конфликт регистрации заметен до прокрутки и не скрывается общим «работают даже когда окно скрыто».

### P2 D-10 — HUD нуждается в завершении проверки, а не новом оформлении

Доказательство: `DesktopHudWindow.kt:97` уже использует WindowDraggableArea после пользовательского бага. Есть режим locked/click-through и reset из Settings. `:88,111–120` длинные строки и footer обрезаются Ellipsis; `:39,40` переданный onHelp не используется. Offscreen проверка выполняется при создании окна (`:66–72`), не как доказанная политика после смены экранов/DPI. Родственные размеры и settings-пересчёт требуют реального drag-test.

Исправление: сначала доказать сохранность геометрии после drag/resize/DPI/restart, затем включить достижимую справку/пояснение закрепления. Контекстные строки могут обрезаться, но текущая активная строка должна читаться при поддерживаемых настройках; крайние size+scale должны иметь адаптивную политику.

Приёмка: drag по центру/краям, resize380×180 и680×240, scale70/100/200%, перезапуск, hide/show, CtrlAltL и reset. Отрицательные координаты второго монитора разрешены, окно не улетает; после отключения монитора есть доступное восстановление. Запрет принудительного закрытия старой копии не обходить; конфликт двух экземпляров отметить отдельно.

## Ограниченный следующий пакет

1. D-01: сохранность черновиков и обратная связь операции; это первый пользовательский дефект с риском потери работы.
2. D-03 + D-02: responsive workspace/dialog sizing и полная desktop theme mapping; не переписывать весь layout одновременно.
3. D-04 + D-05 + D-07: честные состояния медиатеки/тем/диагностики, локализованные blacklistlabels изD-06.
4. D-08 + D-09: единый previewexport и завершённые desktop подсказки/keyboardfocus.
5. Реальная визуальная матрица D-10 и всех6тем. Пока нет изображения/ручного подтверждения, visualgate остаётся PENDING.

Нет оснований утверждать, что вся ПК-версия готова: этот отчёт фиксирует concrete gaps, но не подтверждает ни исправление, ни визуальную приёмку. Интеграция архивов/слияния БД остаётся отдельным функциональным блоком архитектора.

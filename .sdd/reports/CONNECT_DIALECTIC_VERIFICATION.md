# Connect — Ground-Truth Verification
Дата: 2026-10-16. Независимо прочитаны CONNECT_DIALECTIC_THESIS.md и CONNECT_DIALECTIC_ANTITHESIS.md, SPEC-CONNECT-01 и ADR-042/043. Исходники проверены адресно. Продуктовый код не изменялся. Сетевые атаки, захват с физического Android и акустические измерения не выполнялись.

## Вердикт
Узкий положительный тезис подтвержден: есть реальная цепь Android AudioPlaybackCapture → LAN TCP/UDP → Windows SourceDataLine. Это свидетельство интеграции API, а не работоспособности звука. Пользователь сообщает «звук вообще не передается»; ниже локализован сильный кандидат причины, но не выполнено физическое воспроизведение.

## Проверенные дефекты

1. **P1: Audio Cast нарушает PCM контракт и может молча отбрасывать весь звук.** Формат 48000/2ch/16bit/10ms дает 1920 байт: [AndroidAudioCaptureService.kt](C:/Users/DaniilTuT/Documents/antigravity/quick-nobel/app/src/main/java/com/lirix/app/connect/cast/AndroidAudioCaptureService.kt:37). [AndroidCastSourceManager.kt](C:/Users/DaniilTuT/Documents/antigravity/quick-nobel/app/src/main/java/com/lirix/app/connect/cast/AndroidCastSourceManager.kt:139) обрезает PCM до 1200−7=1193 байт (константы [CastDatagramCodec.kt](C:/Users/DaniilTuT/Documents/antigravity/quick-nobel/shared/src/commonMain/kotlin/com/lirix/app/connect/cast/CastDatagramCodec.kt:38)). Сервер пишет payload напрямую в 16bit stereo SourceDataLine: [DesktopConnectServer.kt](C:/Users/DaniilTuT/Documents/antigravity/quick-nobel/desktop/src/main/kotlin/com/lirix/app/desktop/cast/DesktopConnectServer.kt:227), формат :244, write :267. 1193 % 4 = 1. [Официальный Java17 контракт SourceDataLine.write](https://docs.oracle.com/en/java/javase/17/docs/api/java.desktop/javax/sound/sampled/SourceDataLine.html#write(byte%5B%5D,int,int)) требует целое количество sample frames и указывает IllegalArgumentException для некратного len. Exception молча поглощается :268, UDP loop :219 продолжает работать. Поэтому нельзя описывать дефект только как потерю 37.9% данных: стандартные full frames не соответствуют контракту записи и могут полностью исчезать. Codec=OPUS (:89) также противоречит raw PCM и отсутствию Opus decoder на сервере. Это главный кандидат для первичной диагностики тишины; runtime журнал исключения/счетчики отсутствуют.

2. **P1: runtime pairing не аутентифицирует клиента.** [AndroidConnectManager.kt](C:/Users/DaniilTuT/Documents/antigravity/quick-nobel/app/src/main/java/com/lirix/app/connect/AndroidConnectManager.kt:200) посылает нулевые nonce/proof; [DesktopConnectServer.kt](C:/Users/DaniilTuT/Documents/antigravity/quick-nobel/desktop/src/main/kotlin/com/lirix/app/desktop/cast/DesktopConnectServer.kt:167) без проверки создает trusted fixed endpoint и отвечает ok=true :182. Контрольные сообщения передаются из socket напрямую handleMessage :153, SetAudioCast :193 не требует authenticated state. Отдельный PairingSecurityManager в эту цепь не включен. Сценарий: неизвестный достижимый LAN-клиент отправляет PairRequest или SetAudioCast. Это не просто допустимая замена QUIC на TCP по ADR-042: эквивалентная защита отсутствует. [LanConnectTransport.kt](C:/Users/DaniilTuT/Documents/antigravity/quick-nobel/shared/src/commonMain/kotlin/com/lirix/app/connect/transport/LanConnectTransport.kt:63) connectPinned также игнорирует endpointId и relayUrl.

3. **P1: UDP ingress не привязан к сопряжению и разрешению Cast.** [DesktopConnectServer.kt](C:/Users/DaniilTuT/Documents/antigravity/quick-nobel/desktop/src/main/kotlin/com/lirix/app/desktop/cast/DesktopConnectServer.kt:221) принимает sender без проверки, декодирует и при отсутствии audio line автоматически открывает ее :229–230. Сценарий: корректная датаграмма с кратным 4 PCM payload достигает UDP4433 без TCP/QR; либо поздний пакет после SetAudioCast(false) повторно открывает line. Эта независимая ветка остается даже после исправления TCP pairing. Фактическая слышимость зависит от доступности audio device и формата payload.

4. **P1: handoff сообщает вымышленный успех.** [DeviceConnectBottomSheet.kt](C:/Users/DaniilTuT/Documents/antigravity/quick-nobel/app/src/main/java/com/lirix/app/ui/connect/DeviceConnectBottomSheet.kt:529) запускает local FSM, затем через 1500+300ms сам вызывает accepted Ack :537 и isPlaying update :541; это явная demo-ветка :533. [HandoffStateMachine.kt](C:/Users/DaniilTuT/Documents/antigravity/quick-nobel/shared/src/commonMain/kotlin/com/lirix/app/connect/handoff/HandoffStateMachine.kt:66) не отправляет HandoffRequest, а сервер остальные сообщения игнорирует :210. Даже доступный ПК не получает запуска трека этим UI-сценарием. Не утверждается, что физический Android звук обязательно заглушается: подтверждено ложное локальное состояние успеха.

5. **P1: выбор B может отправлять аудио прежнему A.** [AndroidConnectManager.kt](C:/Users/DaniilTuT/Documents/antigravity/quick-nobel/app/src/main/java/com/lirix/app/connect/AndroidConnectManager.kt:177) возвращает любой CONNECTED transport; startAudioCastToDevice :227–231 проверяет только CONNECTED, не endpoint/addrs. [AndroidCastSourceManager.kt](C:/Users/DaniilTuT/Documents/antigravity/quick-nobel/app/src/main/java/com/lirix/app/connect/cast/AndroidCastSourceManager.kt:76) при уже запущенном Cast просто возвращает true. Сценарий: подключиться к A, затем выбрать B; новое успешное подключение к B не гарантируется, старый сокет продолжает использоваться. Исправление должно учитывать и активный Cast, и транспорт.

- Не подтверждено физическое качество звука, задержка, воспроизведение Windows→Android или полный remote player.
- APPROVED ADR не заменяет проверку runtime. ADR-042 описывает TCP/UDP, но не закрывает требования безопасности SPEC-CONNECT-01.

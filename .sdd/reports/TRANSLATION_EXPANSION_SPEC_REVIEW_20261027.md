Reject the homepage as a song page.

## Revised partial-results review

The source DOM correction covers article-local h2/h3 and any-heading boundaries, but Identity item 2 still says `h2` only; change that remaining wording to `h2/h3`.

**Behavioral blocker:** revised aggregation turns existing unique, validated LyricsTranslate `Found` plus a new Rustoeng timeout/403 into `Candidates`, preventing old automatic save. This is a product regression against the stated goal of preserving current automation, and awaiting both providers can add delay or exhaust the global 35-second deadline even when LyricsTranslate already succeeds. No verified LT result should become unavailability-driven manual-only merely because an optional new fallback fails.

Recommended deterministic priority fallback: unique verified LyricsTranslate `Found` → existing automatic transaction immediately, no claim of global uniqueness; LyricsTranslate `Candidates` → explicit user selection; LT clean `Missing` → Rustoeng exact Found or candidates per same policy; LT failure/timeout → Rustoeng available result as candidates with explicit partial-source warning and user confirmation, or failure if no available result; both clean empty → Missing. This intentionally does not claim to enumerate all available providers; an optional future 'other sources' search can be separate. Explicit provider errors, cancellation, current language and existing caches stay correct. If product instead elects to aggregate concurrently, keep old LT-found auto-save and do not block it on the new source; make priority rather than globally-unique language explicit, and ensure UI is truthful about available alternatives.

`Candidates(values, unavailableSources=emptyList())` and matching UI state are source-compatible for constructors, provided all destructuring, equality-sensitive tests, immutable bounds, and exhaustive `when` uses are revalidated. Test not only both healthy and 403, but LT-found+Rustoeng 403/timeout (auto-saved LT), LT ambiguous (manual selection), LT failure+Rustoeng result (visible warning/no replacement), LT missing+Rustoeng exact (auto), both missing, failure+missing, outer cancellation, manual save race, no extra provider network when primary returns early, and correct target. A single source candidate limit remains bounded; if UI displays multiple sources in another mode, do not promise no silent loss while `take(8)` may discard entries — either disclose truncation or explicitly define policy.

When implementing source-specific timeouts, `TimeoutCancellationException` subclasses `CancellationException`: handle the inner provider deadline as incomplete but always rethrow outer parent cancellation. Avoid serial per-source timeouts whose sum exhausts the coordinator's 35-second deadline; define strict bounds and test timings with virtual time and cancel-aware clients. No tests run in this review; actual app behavior under 403 and phone network remains unproven.


## Final revision review — identity gap

The corrected h2/h3 article selectors and ordered LyricsTranslate-first fallback address prior blockers, and provider-local timeout versus parent cancellation is now explicit. `Candidates(values, unavailableSources = emptyList())` is a source-compatible constructor extension subject to implementation checks; a fixed-source localized partial warning and no auto-save after LT failure are appropriate. Rights remain unverified and live/device tests are separate.

**Remaining blocking contract ambiguity:** `TranslationCandidate` carries an expected artist but `TranslationPanel.kt:161-163` reloads only `candidate.sourceUrl`. The proposed fragment `#lirix-song=<original heading>` encodes only the song. After search and before preview, an article can change `entry-title` to another artist while retaining a matching h2/h3; loading only the URL cannot compare that header to the original candidate artist. Checking that *some* unique header exists is not verification of the expected artist. The spec requires both but leaves no implementable source for the expected artist at load. Encode a bounded, stable expected artist+song pair into a validated section reference or explicitly carry expected identity into load/confirm across Android/Desktop and saved sources; test discovery followed by changed artist/title on reload, wrong-artist references, and duplicates. Fail closed or request explicit user reconfirmation; never silently auto-save mismatched identity. Bare/manual URL can require the user to select and confirm an identified section.

Other acceptance safeguards remain as written: verify per-provider timeout vs caller cancellation, LT Found no fallback network and same automatic save, partial warnings localized and clean `Missing` distinct from failure, max candidate bounds, cache/manual preservation and no production full-lyrics fixture. Real device/provider reliability, atypical structures, interrupted request and rights are not established by spec review.

## Actual behavior

- `app/src/main/java/com/lirix/app/ui/LibraryScreen.kt:404–415,545–576` right swipe calls `setFavorite(track.trackKey, !track.isFavorite)` asynchronously, so it **toggles** favorite based on the row snapshot rather than always setting it. Worktree `shared/src/commonMain/kotlin/com/lirix/app/storage/MusicDao.kt:39–43,60–71` (`HEAD:23–27,44–55`) persists to `music_tracks` and observes changes; Favorites list filters `visibleTracks` by `isFavorite` (LibraryScreen:163–168). Two rapid calls before Flow refresh can use the same stale value. Existing atomic `toggleFavorite(track)` runs `insertTrackIfMissing`, `invertFavorite` and read inside `@Transaction`, but adopting it should assess row resurrection semantics if concurrent deletion is ever added.
- Left swipe calls `hideTrack`, which adds a key to `remember { mutableStateListOf<String>() }` (LibraryScreen:150,200–203,575–576). It is only local Compose state; it is not saved to Room and is lost when the screen composition is destroyed/recreated. No DAO DELETE or audio file operation is invoked. Snackbar says “Трек … скрыт из медиатеки” / “Track … hidden from library” and offers Undo (`values-ru/strings.xml:145`, `values/strings.xml:145`, LibraryScreen:205–212). TalkBack action says “Скрыть трек из медиатеки” (`:533–543`, strings:129). Neither specifies temporary nature.
- Probable exact cause of user report: `visibleTracks` is `remember(recentTracks, hiddenTrackKeys)` (`:158–161`). The same mutable list object is mutated, hence the remember key remains equal to itself and the cached filtered list is not recalculated on recomposition unless `recentTracks` also changes. Snackbar can claim hiding while the row remains. This is a reasoned Compose-source finding, **not a runtime reproduction**. Undo mutates the same list and suffers the same cache problem. Fix by making the filter directly read tracked state every recomposition or using `derivedStateOf` appropriately, with a behavioral assertion on actual visible item; do not simply copy or mutate the same remember key without testing.
- `detectHorizontalDragGestures` accumulates x after horizontal slop, threshold `scaledTouchSlop * 4`, preserves a 28dp local row edge for system Back (`:519–520,554–587`). There is no visible drag offset, directional icon or action label during gesture: `dragDeltaX` is used only for threshold (`:523,558,565,570,574,579,583`). Haptic feedback alone occurs on completion. Do not claim device-specific vertical interception without running gesture tests.
- Hide schedules an independent timer per request (`:204–218`); `showSnackbar` serializes messages while each timer dismisses whichever snackbar is current at expiry. A prior timer can dismiss a subsequent message early. Tie each expiry to its actual displayed snackbar or use an appropriate supported duration; verify queued actions and accessibility-recommended timeout.

## Data boundaries and minimal safe change

`TrackEntity` contains favorite, listening totals/counts, local user notes and copied lyrics (`shared/src/commonMain/kotlin/com/lirix/app/storage/MusicEntities.kt:26–41`). Session and lyrics cache entities (`:47–59,78–88`) do **not** declare Room foreign keys despite the lyrics comment at :75. `deleteTracksByKeys` (MusicDao worktree:97–98, HEAD:81–82) deletes only `music_tracks`; sessions and cache have separate DAOs and can remain orphaned, while row-local notes/favorite/stats may be lost. It does not access or delete an audio file. `LibraryArchive.kt:136–137` exports tracks, sessions and cache separately. Playback may recreate a track, but preservation of its data and undo under concurrent replay is not guaranteed by this audit. Existing blacklist purge explicitly deletes tracks/sessions (`BlacklistPurgeEngine.kt:67–68`) and is a different, destructive feature, not authorization for library swipe.

Recommended bounded policy pending any user decision about permanent removal: keep reversible temporary hide, clearly label it “temporarily hide” at the gesture and snackbar, fix filtering immediately, use per-snackbar lifetime, and offer action/Undo that exactly matches visible behavior. Keep music file, history, lyrics and notes untouched. State explicitly that exiting/recreating the screen restores hidden rows; do not imply permanent hiding. For a durable hidden library, implement a separately designed persistent hidden state plus restoration path and backup policy; for true deletion, explicitly define history/lyrics/notes preservation and robust Undo first. Verify horizontal vs vertical gestures/system Back, repeated left swipes and queued Undo, toggling favorite twice rapidly, filtering, screen recreation and localized/accessibility labels. Existing tests found by search do not exercise these actual library swipes.

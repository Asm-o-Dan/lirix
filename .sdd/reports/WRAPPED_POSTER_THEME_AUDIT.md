# Wrapped и постеры: аудит и направление обновления

Дата: 2026-10-16. Автор: Codex. Область: расчет итогов, WrappedScreen, Wrapped/NowPlaying export и система тем. Это аудит исходников и проектное предложение; реальные экспортированные PNG в этом проходе не рендерились, продуктовый код не менялся.

## Вывод

Экран итогов уже частично приведен к Graphite/Paper. Экспорт остается старым Canvas-рендерером с отдельными стилями и жесткими цветами. Передача isDark вместо полного набора токенов теряет выбранную тему. Данные и текстовые выводы также расходятся: кэш текста назван просмотром, число запусков — долей времени. Нужны единый снимок данных и единый снимок оформления для UI/preview/export.

## Проверенные проблемы

### 1. P1 — данные не соответствуют подписям

- `WrappedScreen.kt:313,327` считает «Просмотрено с текстом» как uniqueTracks×lyricsCoverageRatio.
- `shared/.../analytics/WrappedStatsEngine.kt:243` рассчитывает coverage по наличию plainLyrics/syncedLyrics, а не событию открытия текста. Это наличие текста в каталоге, не использование пользователем; даже пустая непустая-null строка засчитывается.
- `WrappedStatsEngine.kt:384` и далее распределяет сессии по часу начала и увеличивает счетчик на1; `WrappedScreen.kt:552` описывает результат как процент времени. Десять запусков по5сек перевешивают одну сессию30мин.
- `WrappedScreen.kt:559` при отсутствии явного >50% пика пишет «равномерно», включая пустую историю. Например49/49/1/1 не является равномерностью.
- `ListeningArchetype.GENRE_NOMAD/ACOUSTIC_BARD` выводят жанры/исполнение из разнообразия артистов и наличия кэшированного текста. Это игровые интерпретации, не измеренные факты.

Решение первого этапа: честно переименовать метрики, не изобретать прошлые события. Для реальной длительности по времени суток нужен отдельный контракт пауз/границ периода; хранить только общий duration и start/end недостаточно для точного распределения пауз внутри сессии.

### 2. P1 — NowPlaying export игнорирует светлую тему

`NowPlayingScreen.kt:1663` не передает isDark в generateNowPlayingCard; default в `ShareCardGenerator.kt:990` — true. Светлый экран экспортирует темный постер. Wrapped передает `PosterStyle.forTheme(lirixColors.isDark)` (`WrappedScreen.kt:141`), но все темные темы сводятся к Graphite, все светлые — к Paper, включая Spotify/Yandex/Pastel.

### 3. P1 — изменение палитры не охватывает helper-функции

`ShareCardGenerator.kt:137` затеняет локальными переменными объектные COLOR_*, но `drawFooter:1416`, `drawPlaceholderArt:1467` и другие helper читают старые константы. Footer рисует фиолетово-голубой градиент и текст старым muted цветом, жестко пишет `MUSIC TRACKER // VERIFIED AUDIO REPLAY // 2026`. Выбор Paper не делает весь рендер светлым. Год и «verified» не подтверждены данными.

### 4. P1 — обложка может принадлежать другому треку

`WrappedScreen.kt:122` загружает topTracks через mapNotNull, удаляя пропуски. `ShareCardGenerator.kt:534` затем выбирает bitmap по индексу idx. Если у первого трека нет обложки, обложка второго становится первой. Нужна Map<trackKey,Bitmap?>, а не сжатый список без идентичности.

### 5. P2 — тяжелая генерация выполняется на UI-контексте

`ShareFormatDialog.kt:53,123` вызывает suspend callback через rememberCoroutineScope, который начинает работу на Main. В callback `WrappedScreen.kt:110` и `NowPlayingScreen.kt:1644` синхронно выполняются decodeFile и Canvas rendering; suspend ShareManager переключает IO только после их выполнения. `drawAlbumCoverCollage:1134` повторно читает файлы и достраивает24 искусственные обложки даже для CollageMode.NONE. Нужны одно декодирование с downsample, чистый renderer и явный dispatcher.

### 6. P2 — типографика и меню экспорта живут отдельно от темы

`ShareFormatDialog.kt:57` использует AppColors, CyberCyan/HyperViolet и эмодзи вместо LirixThemeTokens. Canvas берет Typeface.DEFAULT/SERIF/MONOSPACE. Имена мобильных LiterataFontFamily/GolosTextFontFamily в `app/.../ui/theme/Type.kt:17` сейчас являются alias для generic Serif/SansSerif; реальные ttf найдены только в shared/src/desktopMain/resources/fonts. Нельзя считать совпадение имен доказательством наличия шрифтов на Android.

### 7. P2 — макет зависит от ручных curY и непроверенных лимитов

FULL Stories включает много блоков с фиксированными приращениями curY; footer стоит независимо у нижней границы. Полного измерения content bounds нет. Переполнение пока риск по коду, не подтвержденный скриншотом дефект. `drawMultilineText:1485` не возвращает измеренную высоту. Existing ShareCardGeneratorTest в основном проверяет размер bitmap/null, а не отсутствие наложений/обрезаний/контраст.

### 8. P2 — период и live snapshot требуют отдельной точности

MONTH — последние30×24ч, WEEK — последние7×24ч, фильтр по старту сессии. Сессия, начавшаяся до границы, полностью выпадает; пересечение границы не обрезается. Подпись должна явно говорить «30 дней» до введения календарного периода. У активной сессии livePos/wall-time используются как длительность; паузы/seek могут завысить слушание. UI имеет два эффекта пересчета и обновляет live статистику каждые3сек. Для экспорта нужен единый замороженный referenceTimestampMs и набор данных, а не метрики разных моментов.

## Новый вид

Итоги: спокойная журнальная страница. Одна ведущая метрика времени, точный диапазон дат, три популярных трека, короткое наблюдение только при достаточных данных, достижения ниже. Пустая история имеет свое состояние. Никаких выдуманных жанров, «пения» и равномерности при отсутствии данных.

Постеры: единая система из трех композиций — «Итоги периода», «Топ треков», «Сейчас играет / строка песни». Graphite — темный графит, светлый текст и один сдержанный акцент; Paper — теплый лист, чернила и один синий акцент. Для остальных сохраненных тем — тот же макет с полными активными токенами. Тема и композиция независимы. Фон обложки не должен мешать чтению.

Экспорт: preview → композиция → формат → тема «Как в приложении» по умолчанию → поделиться/сохранить. Предпросмотр и итоговый PNG рисует один renderer. Случайные стили убрать из основного пути, старые экспериментальные варианты можно сохранить как отдельный opt-in позже.

## Порядок работ

1. Исправить явный isDark default, mapNotNull/index artwork и Main-thread rendering.
2. Ввести PosterThemeSnapshot и передавать его во все draw helpers; единые реальные шрифты Android/Canvas.
3. Создать измеряемые, тематические layout templates и preview. Проверить 6 тем×2 формата, длинные названия и отсутствие обложек.
4. Исправить подписи текущих метрик и empty state без миграции.
5. Отдельным analytics CR уточнить периоды, duration/pauses/live, события реального открытия текста и пороги игровых архетипов.

Connect ремонт выполняется другим исполнителем, файлы аудио с этим пакетом не пересекаются. Реализацию этого предложения пока не запускали.

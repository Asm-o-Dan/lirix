## 1. UX-Критика текущего интерфейса (Impeccable Audit)

### 🔴 Проблема 1: Перегруженная шапка (Top Bar Clutter)
Сейчас в шапке 8px отступами в одну линию сжаты:
- Кнопка Назад
- Заголовок трека (название + артист)
- Тумблер [🌐 Серфинг / 🎯 Инспектор]
- Иконка Импорта правила
- Иконка Закрыть

**Вердикт UX**: В портретной ориентации смартфона (ширина 360-390dp) элементам катастрофически тесно. Названия трека обрезаются, тумблер режимов зажат между двумя иконками, а нажатие на «Серфинг» легко приводит к случайному нажатию на кнопку «Назад» или «Импорт».

### 🔴 Проблема 2: Захламление нижней шторки действиями второго порядка
В нижней шторке сейчас одновременно:
- Чип селектора
- Число блоков и строк
- Кнопка «✕ Сбросить»
- Превью 3 строк текста
- Кнопка «Привязать к треку» (Mint)
- Кнопка «Сохранить правило» (HyperViolet)
- Кнопка «Поделиться правилом» (Share icon)

При добавлении новых функций (исключение потомков, выбор Аккорды/Текст) экран превратится в кашу («dashboard slop»).

## 2. Новая Эргономика: Чистая шапка + Троеточие (Overflow Menu)

### 2.1. Реорганизация Шапки (Top Bar)
Оставляем только критический контекст и прямое переключение:
1. **Слева**: Кнопка «Назад» (если есть история в WebView) + Крестик закрытия экрана.
2. **По центру**: Название трека и текущий домен (индикатор статуса).
3. **Справа**: 
   - Компактный двухпозиционный переключатель (Pill Capsule): **[🌐 Сёрфинг]** | **[🎯 Инспектор]**
   - Кнопка **⋮ (Меню дополнительных действий)**.

### 2.2. Что переносится в меню ⋮ (Overflow Menu):
Все вторичные и сервисные действия прячутся в меню с четкими иконками:
1. 📥 **Импорт правила из буфера** (ранее была отдельная кнопка на панели).
2. 📤 **Экспорт / шеринг текущего правила** (убираем отдельную иконку из нижней панели).
3. 🔄 **Очистить все выделения и сбросить**.
4. ⚙️ **Тип контента по умолчанию**: [Текст песни / Аккорды].
5. 🌐 **Открыть в системном браузере**.

## 3. Нижняя Плашка Управления (Inspector Dock 2.0)

Когда пользователь переходит в режим **🎯 Инспектор** и выбирает элемент:

```
+-----------------------------------------------------------+
|  [🟣 div.w-words__text]  [🔴 2 вырезано]      [▲ Род.] [✕] |  <-- Селектор и навигация
+-----------------------------------------------------------+
|  🎯 Захват:  (•) 📝 Текст песни      ( ) 🎸 Аккорды       |  <-- Тип данных
+-----------------------------------------------------------+
|  Превью: "Куплет 1: А ну давай ломися и дави на педаль..."|  <-- Чистый текст (без вырезанных)
+-----------------------------------------------------------+
|  [⚡ Сохранить и привязать к треку]                        |  <-- ЕДИНСТВЕННАЯ главная кнопка!
+-----------------------------------------------------------+
```

### Ключевые решения эргономики:
1. **Объединение кнопок «Привязать к треку» и «Сохранить правило»**:
   - Пользователю не нужно думать, какую из двух кнопок нажимать! Пользователь пришел обучить приложение для этого сайта.
   - Единая акцентная кнопка: **«Сохранить правило и привязать»** (HyperViolet gradient).
   - Она автоматически:
     1. Создает и сохраняет `CustomLyricsRuleEntity` с динамическим `search.urlTemplate`.
     2. Записывает текст/аккорды в кэш текущей песни.
     3. Возвращает пользователя в плеер с уже играющим текстом.
2. **Селектор типа контента (Segmented Control)**:
   - Переключатель: **[📝 Текст песни]** / **[🎸 Аккорды]** прямо над кнопкой сохранения.
   - Если выбраны «Аккорды», данные автоматически валидируются через парсер аккордов и сохраняются в `chordsSelector` и `chordsAmDm`.
3. **Интерактивное вырезание потомков (Strip Exclusion)**:
   - При тапе внутри уже выделенного фиолетового родителя элемент подсвечивается **красным контуром с зачеркиванием** (`🔴 Strip`).
   - В плашке появляется бейдж: `[🔴 2 вырезано]`.
   - Текст этого элемента немедленно вырезается из предпросмотра!
   - Повторный тап по красному элементу снимает исключение.
4. **Кнопка [▲ Родитель]**:
   - Позволяет в один тап подняться на уровень выше, если пользователь случайно нажал на конкретное слово или строчку вместо всего куплета/блока.

## 4. Защита сенсорного ввода (Zero Slop Touch Engine)

В `teach_inspector.js`:
1. **Детектор жестов (Gesture Arbitrator)**:
   - В `touchstart` запоминаем `startX, startY`.
   - В `touchmove` вычисляем гипотенузу $\Delta = \sqrt{dx^2 + dy^2}$. Если $\Delta > 8\text{px}$, жест помечается как `IS_SCROLLING`.
   - В `touchend`: если был скролл — событие полностью игнорируется, выделения не происходит. Выделение срабатывает **строго при статичном тапе** ($\Delta \le 8\text{px}$).
2. **Устранение мульти-триггеров**:
   - Слушаем только `touchend` на сенсорных устройствах.
   - Защитный флаг `lastTapTimestamp` с отсечкой 300мс блокирует дублирующие синтетические события `click` и `pointerup`.
3. **Устранение слепого `parentElement`**:
   - Клик по тексту точно выбирает целевой DOM-узел без принудительного перескока через `SPAN`.

# INTAKE: LYR-COMMUNITY — пользовательские источники текстов, обмен правилами и отклонение источника

- **Статус:** GATE 0 PASSED (подтверждено пользователем 2026-10-04)
- **Владелец процесса:** Координатор
- **Следующая фаза:** ARCHITECTURE (Архитектор)

---

## 1. Цель

Если встроенные провайдеры (LRCLIB, AmDm и т.д.) не нашли текст или нашли неверный, пользователь должен уметь:
1. отклонить неподходящий результат и автоматически перейти к следующему источнику;
2. сам найти текст на любом сайте прямо с телефона и одним действием «научить» приложение этому сайту (сгенерировать правило-парсер);
3. делиться созданными правилами с другими пользователями и получать их правила.

## 2. Подтверждённые решения пользователя

| Вопрос | Ответ |
|---|---|
| Где ищется текст | **На телефоне** → десктопное расширение НЕ приоритет; основной путь — внутри приложения / Android Share |
| Делиться правилами | **Да, обязательно** → нужен общий реестр правил |
| Поэтапность | B (Share intent) → C (WebView teach mode) → общий реестр |

## 3. Функциональные требования

### FR-1. Отклонение источника («Не тот текст»)
- На экране NowPlaying (вкладки Караоке/Текст/Аккорды) пользователь может пометить текущий найденный текст как неподходящий.
- После отклонения приложение пробует **следующий источник** в цепочке провайдеров (встроенные + пользовательские + общие правила).
- Если источников больше нет → состояние **«Текст не найден»** (с предложением «Найти в интернете» → FR-3).
- **Отмена:** пользователь может отменить отклонение (undo сразу после действия и позже — восстановить отклонённые источники для трека).
- Отклонения **персистентны** (переживают перезапуск), привязаны к треку и источнику; фоновый prefetch и кэш текстов обязаны их учитывать (не возвращать отклонённый результат повторно).
- Отклонение результата пользовательского/общего правила — сигнал качества для этого правила (учитывается в FR-5).

### FR-2. Приём текста через «Поделиться» (MVP)
- Из любого браузера телефона: выделенный текст или URL → «Поделиться» → Music Tracker.
- Выделенный текст сохраняется как текст текущего/выбранного трека.
- Для URL — попытка автоизвлечения (эвристика основного текстового блока) или открытие в режиме обучения (FR-3).

### FR-3. Режим обучения во встроенном браузере (генерация парсера)
- Кнопка «Найти в интернете» открывает WebView с поиском «артист + название + текст».
- Пользователь переходит на сайт, тапом выделяет блок текста (подсветка), подтверждает.
- Приложение сохраняет текст для трека **и** генерирует декларативное JSON-правило для домена (селектор контента, удаляемые элементы, опционально селектор аккордов, шаблон поиска по сайту и селектор ссылки результата).
- Правило становится **пользовательским провайдером** и участвует в цепочке поиска для других треков.

### FR-4. Управление источниками
- Экран «Мои источники»: список встроенных, пользовательских и подключённых общих правил; порядок приоритета, включение/выключение, удаление; пометка «правило сломано».

### FR-5. Обмен правилами (community)
- Публикация своего правила в общий реестр и подключение чужих.
- Нужны: версионирование правил, валидация перед применением, защита от вредоносных/спам-правил, рейтинг/сигналы качества (успешные извлечения vs отклонения из FR-1).

## 4. Ограничения и нефункциональные требования
- Chrome Android не поддерживает расширения → основной UX — внутри приложения.
- Offline-first: локальные правила работают без сети; общий реестр синхронизируется при наличии сети.
- Правило — **данные (JSON), не исполняемый код**.
- Сайты с JS-рендерингом должны поддерживаться (WebView-извлечение, не только статический HTML).
- Не ломать существующие провайдеры, кэш текстов и Room-миграции (сохранность пользовательских данных).

## 5. Открытые вопросы для Архитектора
1. Где хостить общий реестр при минимальной инфраструктуре (GitHub-репозиторий с JSON + индекс, свой бэкенд, иное) и как пользователь публикует правило без аккаунтов/с аккаунтом.
2. Модель данных: таблицы правил, отклонений, статистики качества; миграция Room.
3. Порядок и приоритет источников в цепочке; как отклонения влияют на prefetch.
4. Механика выделения в WebView и генерации устойчивого селектора.
5. Безопасность и модерация общих правил.

## 6. Definition of Done (уровень эпика)
- Пользователь может отклонить текст, приложение переходит к следующему источнику, при исчерпании показывает «Текст не найден», отклонение отменяемо.
- Пользователь может с телефона научить приложение новому сайту и этот сайт находит тексты для других треков.
- Пользователь может опубликовать правило и подключить чужое.
- Все тесты зелёные, установлено и проверено на Poco M7.

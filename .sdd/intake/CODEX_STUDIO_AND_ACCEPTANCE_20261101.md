## Этап A. Редизайн студии

### Проблемы (с телефона, Android 15, ≈384 dp)
- «Применить к песне» уходила под полосу жестов (см. выше).
- 16 элементов управления подряд одинаковыми жёлтыми текстовыми кнопками; режимы «Текст/LRC» и разрушительное «Убрать метку» в одной строке.
- «Метка: не поставлена» — моноширинный акцентный шрифт: обычное состояние выглядит как ошибка.
- «Реакция: 200 мс» и «− +» разнесены по краям, у «− +» нет доступных имён; рядом несвязанные «−5 с / +5 с».
- Текущая строка дублируется (крупно и в списке).
- Строки авторства («муз. …», «сл.», «В. Лебедев и …») идут как строки песни.
- «Tap-to-Sync» не переведён; выбранный чип режима почти не отличим.
- Точный режим: пустая шкала без аудио; курсор шкалы на 00:00, когда трек на 01:06; «15 с» и «− +» масштаба висят отдельно.

### Целевая компоновка
1. **Шапка**: название/исполнитель, «Закрыть»; переключатель режимов (сегментированная кнопка, локализованные «Быстро» / «Точно»); полоса прогресса «Размечено N из M» вместо двух серых строк статуса; статус черновика — вторичным текстом.
2. **Центр**: крупная текущая строка; одна главная кнопка «Поставить метку» (быстрый режим) или шкала с волной (точный режим). Список строк ниже — без повтора текущей строки сверху (или с подсветкой в списке без отдельного дубля).
3. **Закреплённый низ** (вне прокрутки, с отступом навигации): время, Play/Pause иконкой, «К плееру», «Применить к песне» (основная кнопка, ≥48 dp, растёт со шрифтом).
4. **«Дополнительно»** (раскрываемый блок или «⋮»): реакция с подписанными «Уменьшить/Увеличить задержку реакции», ±5 с, «Исходник», «Текст», «LRC», A–B, «Сдвинуть фрагмент», «Ввести время строки». «Убрать метку» — отдельно, с отменой.
5. **Строки авторства**: при открытии предложить «Пропустить строки авторства (N)»; распознавание — чистая функция в `KaraokeStudioEngine` с тестами (позитив: «муз.», «сл.», «Music by», «Lyrics by»; негатив: обычные строки, содержащие эти слова в середине). Не удалять строки из исходного текста без явного согласия.
6. **Точный режим**: курсор шкалы следует за воспроизведением, пока пользователь не взаимодействует со шкалой (уже есть флаг `follow`); подсказка «Выберите аудио для волны» внутри пустой шкалы, а не отдельной кнопкой; подписи масштаба рядом со шкалой.
7. Цвета — только `LirixThemeTokens`; состояния «не размечено» — вторичный цвет, ошибки — error-токен; все строки — ресурсы RU/EN; зоны касания ≥48 dp, интервалы ≥8 dp; без фиксированных высот текстовых кнопок.

### Шаги
1. Снимки «до» на телефоне в обоих режимах (`adb exec-out screencap -p`, `uiautomator dump`) — в `.gradle/` или временную папку, **не в репозиторий** (на экране личные данные).
2. Макет новой компоновки (ASCII/Compose-превью/картинка) → **согласовать с пользователем** до реализации.
3. Реализация в файлах зоны Codex; движок, черновики и формат LRC не менять, кроме чистой функции распознавания авторства.
4. Тесты: `KaraokeStudioEngineTest` (авторство), `StudioTimelineGeometryTest`, `KaraokeStudioDraftStoreTest`, `KaraokeStudioDurationTest` — без ослабления существующих проверок; при необходимости — Compose UI-тест в `app/src/androidTest` на видимость «Применить» и порядок фокуса.
5. Установка на телефон — **только после согласия пользователя**: `./gradlew :app:assembleDebug`, затем `adb install -r app/build/outputs/apk/debug/app-debug.apk` (данные сохраняются; не делать `uninstall`). Не размечать и не применять тайминги к песням пользователя без его согласия.

### Критерии приёмки
- [ ] «Применить к песне» видна целиком и нажимается в обоих режимах при 100/150/200 % шрифта.
- [ ] На первом экране быстрого режима ≤6 видимых действий; остальное — в «Дополнительно».
- [ ] Все элементы имеют доступные имена; TalkBack читает: статус → текущая строка → «Поставить метку» → низ.
- [ ] Строки авторства можно пропустить одним действием; без согласия исходный текст не меняется.
- [ ] Курсор шкалы следует за воспроизведением.
- [ ] Нет литералов строк в Kotlin; RU/EN ключи парные.
- [ ] Тесты студии и `:app:testDebugUnitTest` проходят.

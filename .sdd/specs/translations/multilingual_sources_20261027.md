# Multilingual song sources, first expansion — 2026-10-27

## Outcome and boundaries

Automatic title+artist discovery should offer English translations of Russian songs and continue existing ru/en/es/pt/zh translations on Android and Desktop. Add Rustoeng as an English-target provider, retain Amalgama and LyricsTranslate, preserve existing selections and caches, and show true provenance/author. Translation target, original language and UI locale are separate; do not infer one from another. No machine translation, karaoke timing, line alignment or automatic source-language classification. Do not overwrite the unrelated dirty main Lyrsense integration, TranslationPanel localization/reading layer, and player/desktop changes. Implementation and test on isolated canonical HEAD, plus a narrowly adapted patch to main; freeze and compare both against preservation copies before staging.

## Current evidence, not an availability guarantee

- Rustoeng describes Russian→English author translations; [5’Nizza/Soldier (Солдат)](https://rustoeng.com/5nizza/) exposes the artist in the article header and an `h2` bilingual song heading, a translation and no observed Russian text. [Okudzhava](https://rustoeng.com/okudzhava-bulat-4/) contains multiple songs: first heading `h2`, second heading `h3`, on the same artist page. The site can contain multiple page-level `h1` elements, so global first-h1 selection is unsafe. The public WordPress search is `https://rustoeng.com/?s=...`; search responses include unrelated navigation and must be restricted to actual result entries. See `.sdd/reports/TRANSLATION_EXPANSION_RESEARCH_20261027.md` for dated observed 200 responses, not device acceptance.
- [Kipelov — Я свободен](https://lyricstranslate.com/en/kipelov-ya-svoboden-english) is a Russian original / English translation; multiple English translations exist. LyricsTranslate is already in HEAD; its exact normalization can reject a Cyrillic player artist when site returns a Latin spelling. Research observed live form and candidates, but the existing all-target live test uses an originally French song and is opt-in.
- Rustoeng says free-to-use, but scope for app caching/distribution and underlying song rights has not been established. Preserve attribution; check applicable source terms and obtain any necessary rights before distribution. Robots rules are not a content licence. Respect 403/429 and ordinary request limits; do not evade access controls.

## Identity and matching

1. A candidate must carry a unique source link, artist, original song title and where available translation title/translator. Do not use English `Soldier` as evidence that original song is English. Rustoeng EN is the target, because the site declares its corpus; do not fabricate a separately verified source language in `SongTranslation`, which currently has no such field. Preserve source-language uncertainty.
2. Normalize punctuation, apostrophes, Unicode and whitespace for exact identity. Match the Russian title extracted from a bilingual `h2` or `h3` independently of its English title; preserve editions and reject wrong artists/versions. `5’nizza` and `5nizza` must match via unambiguous punctuation normalization. Do not treat transliteration or similarly spelled artist names as proven identity; Cyrillic/Latin aliases require explicit verified source aliases or candidate confirmation. Ambiguous metadata, alternative artists/editions, duplicate headings and multiple translations must produce candidates or a clear failure, never a synthetic exact match.
3. Restrict search parse to actual response entries, never header/menu/sidebar links; ignore untrusted external or non-song pages. Bound searches by candidate count, document size and timeout, do not enumerate entire catalog. Artist from the uniquely matched article header and the selected song heading must independently match the requested artist/song before automatic acceptance; fail closed when missing, modified or ambiguous. Disallowed/unsupported source/target must not masquerade as a translation.
4. LyricsTranslate: support exact Cyrillic and page-reported bilingual titles/artist aliases only where directly evidenced, without weakening version matching or permitting romanization as an English translation. A source query with multiple English variants returns `Candidates` and the existing confirmation path, not an arbitrary first translation. Keep its validated HTML target-language heading, preserve translator/warnings/source, and distinguish service error from Missing.

## Rustoeng DOM boundaries and conservative selection

Resolve exactly one `article` containing both `header.entry-header h1.entry-title` and `.entry-content`; require exactly one nonempty artist title in that header. Never select the first global `h1`: page site title, article title and sidebar Search can all be `h1`. Exclude sidebar, site header/footer, navigation and search-result snippets from both artist and lyric parsing. If article, header or content is missing or nonunique, signal source format/identity error rather than guessing.

Within that same `.entry-content`, walk DOM in document order and identify bilingual song headings in `h2` **or `h3`**. Only allow a heading as a song when a parser extracts a nonempty target title and an unambiguous parenthesised original title, with no unparsed trailing title content; punctuation and nested title parentheses must be handled conservatively. Identified headings receive candidate references even if not selected; duplicate normalized original titles or otherwise ambiguous heading syntax cannot produce an automatic match. Never identify a song based on metadata in `nav`, related links, videos, comments or arbitrary menu text. If the source uses a legitimate heading whose original/target fields cannot be identified, offer no unverified song; report a source-format/ambiguity failure as appropriate.

For body extraction, the first subsequent heading of **any level `h1`–`h6` inside entry-content** ends the selected song, regardless of whether it parses as a song. Also stop at known terminal widgets such as WordPress sharing/related content; skip embedded video, captions, scripts, styles, comments and navigation; do not include links or widget labels as translated lyric text. This conservative boundary means a non-song heading such as `Share this:` cannot bleed into translation, and the h3 `A Forest Waltz (Лесной Вальс)` ends the preceding h2 section. If an unknown heading interrupts selected content or makes boundaries uncertain, surface format/ambiguity instead of returning a potentially truncated or combined auto-translation. Known terminal widget boundaries are valid termination. Compare exact selected heading to reference after reload and reject duplicates before extracting any body. These are source-layout rules, not general HTML heuristics or a promise that every page in this catalog is supported.

## Multiple songs and identity contract

Rustoeng artist pages can hold multiple songs, so `load(pageUrl)` alone is insufficient. A stored candidate and `SongTranslation.sourceUrl` must identify both page and section; do not use only URL or first section. Use a stable, namespaced section reference `#lirix-v1=<base64url-no-padding(UTF-8 JSON array [artist,title])>`, generated from the actual uniquely validated article artist and selected original song heading at discovery. Both values are the exact trimmed source identity, not a guessed player alias. Preserve original strings for display but compare via the same strict normalization policy used for discovery. The page, expected artist and selected song form one identity: `load(candidate.sourceUrl)` must decode both, re-read the page and verify current article artist **and** the song heading against the encoded expected pair, also rechecking expected requested target language. A changed/missing artist, heading, or duplicate normalized matching headings fails explicitly or requests reselection; never select first or silently display another artist/song.

Accept only HTTPS on explicit Rustoeng host allowlist, default port, no userinfo/query on song-page URLs, no path traversal/encoded slash and only this single namespaced fragment. Enforce encoded fragment <=1024 ASCII bytes, decoded UTF-8 <=512 bytes, exactly two nonblank strings each <=200 Unicode code points, valid UTF-8 and no controls; reject invalid base64url, padding, alternate fields, duplicate/extra fragment syntax, malformed/oversized JSON, host changes and noncanonical encoding. Construct outgoing URL and fragment by encoding a validated typed identity, never interpolating raw text. Strip the fragment before HTTP so it cannot affect network routing; apply existing safe redirects and revalidate final page URL. Preserve validated fragment in candidate/sourceUrl as stable per-section key. Opening it in browser may land at the page, so attribution labels must not promise a native anchor. Verify Unicode/apostrophe JSON/base64url round trip and stable reference across unrelated section reorder; no positional indices or unrestricted URL forwarding.

`SongTranslationProviders.load(url)` must dispatch a validated Rustoeng page+section reference; bare artist URLs with multiple sections cannot silently select one. Keep the same signatures for Android/Desktop callers, or update all callers and tests in one change. Since `(trackKey,language,sourceUrl)` is the primary key, section-qualified URLs distinguish sections without migrating the schema. Do not collapse candidates with same page URL before including section fragment. The `TranslationCandidate` list and `TranslationPanel` selection flow must pass the full reference to load and still require manual confirmation for non-exact/ambiguous cases.

## Translation-only pages / UI contract

For Rustoeng store `SongTranslation(sourceName=Rustoeng, language=en, aligned=false, blocks=[TranslationBlock(original="", translated=<selected section>)])`, translated title and real author only if supplied. Do not copy English text into `original`, `MusicTrack.plainLyrics` or synced lyrics; absence is not an empty translated paragraph and is not a song-match signal. Existing serialized documents remain readable, and successful automatic insertion still uses `SongTranslationDao.saveAutomaticIfEmpty` under transaction. Existing manual variants are never removed or replaced automatically.

Current `TranslationPanel.kt:227-257` already uses player-supplied `original` for Original mode, but Together loops blocks and can show a blank per-line original; merely storing `original=""` will not satisfy this task. Update Together for **all `aligned=false` documents** to render two independent text sections (or columns on wide UI), sourcing original from the independently stored `original` argument first, then only actual document original if present, otherwise explicit localised unavailable text. Translation comes exclusively from the translated block. Explain that texts are independent; never imply a line-by-line or karaoke alignment and never show placeholders once per lyric line. Translation-only mode displays only English; Original mode displays independently stored original or unavailable. Preserve existing aligned Amalgama display, previews, reading-layer hook and compact mode. Add RU/EN copy and semantic tests, without replacing the main dirty localization/romanization edits.

## Network, concurrency and fallback

HTTP(S) host allowlist `rustoeng.com` / explicitly permitted `www.rustoeng.com`; no userinfo, arbitrary port, scheme downgrade, traversal, path-encoded slash, or external redirect. Read using existing bounded JVM client if it actually supports query and expected content type; otherwise implement bounded connect/read, redirect count, HTML MIME and bytes, cancellation, explicit 403/429 backoff; no workaround of service blocking. Query must be encoded, not concatenated unescaped. `refresh` bypasses stale local miss cache; provider unavailability and changed markup propagate an error, never Missing. `Missing` means verified completed search without candidates.

For `en`, preserve existing LyricsTranslate priority and its successful behavior; Rustoeng is a fallback, not a parallel completeness guarantee. Keep current candidate order and manual choice; do not claim that results list covers every source. For `ru/es/pt/zh` retain prior provider routing and the dirty main Lyrsense wiring. Provider-level budgets must finish within the coordinator's 35-second timeout and leave time for the fallback and publishing, while external cancellation must never turn into a provider timeout. HTTP 403/429, per-provider timeout, changed markup and network failure are failures, not confirmed Missing.

Make partial fallback results explicit without breaking existing call sites: extend `TranslationSearchResult.Candidates(values, unavailableSources: List<String> = emptyList())` and `AutomaticTranslationState.Candidates(values, unavailableSources: List<String> = emptyList())`; names come from a fixed application-defined provider list, not raw HTML, exception strings or URLs. Default empty list retains old constructors/candidate rendering. `AutomaticSongTranslations.resolve` passes both `values.take(8)` and the bounded distinct source list through to state; existing UI shows a localized RU/EN notice such as “Не все источники ответили; показаны доступные варианты” when the list is nonempty, preserving candidate selection and explicit preview/confirm. Never leak exception contents into UI.

Deterministic ordered fallback for `en`:
- LyricsTranslate `Found` → return it unchanged, preserving existing automatic save via `saveAutomaticIfEmpty`; do not query or wait for Rustoeng and do not claim global source uniqueness. LyricsTranslate `Candidates` → return unchanged for user selection; do not arbitrarily select first.
- LyricsTranslate completed with confirmed `Missing` → query Rustoeng. Its unique, fully verified exact `Found` remains eligible for normal auto-save; its ambiguous candidates require preview/confirmation. A Rustoeng failure/timeout → `Failed`, not Missing. Both independently completed with no candidates → `Missing`.
- LyricsTranslate unavailable, blocked, format-invalid or timed out → query Rustoeng. If it yields a verified `Found` or candidates, return `Candidates` with available results and LyricsTranslate in `unavailableSources`, even if there is only one candidate: show partial notice and require preview/confirmation before any save. Convert `Found` to a `TranslationCandidate` with validated section URL, title, artist and translator; preview reloads that exact reference. No result or failure from the fallback in this case → `Failed`, never Missing. Repeated retry remains possible.
- Enforce each provider budget with a nested `withTimeoutOrNull` owned by that provider: only its own timeout produces a provider timeout result; outer caller cancellation or the coordinator's timeout must propagate, never silently continue or save. Do not generically catch `TimeoutCancellationException` as if every timeout belonged to the current provider. No cancelled/stale result is committed. Refresh bypasses miss TTL as today; a failed/partial search never overwrites or hides an existing cached/manual choice.

Tests exercise production aggregator and coordinator/UI for LyricsTranslate Found + a Rustoeng source that would return 403 (prove Rustoeng not called, Found and existing auto-save preserved), LT Candidates (fallback not called), LT Missing + Rustoeng exact Found/candidates/Missing/403, LT 403 or timeout + Rustoeng Found/candidates with warning and no automatic write, LT failure + Rustoeng Missing/failure as Failed, outer cancellation, and manual-save race. Assert only fixed provider names appear in the warning and `Candidates(values)` with default empty unavailable sources stays backward-compatible. An already saved selection stays available and causes no overwrite or network search.

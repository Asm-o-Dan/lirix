## Задача SPI-P2-008: Реализовать NodeSpec и метаданные узлов

**Модуль:** `:pipeline:nodes-api`  
**Целевые файлы:** `pipeline/nodes-api/src/main/kotlin/com/example/npc/pipeline/nodes/api/spec/`  
- `NodeSpec.kt`
- `NodeCategory.kt`
- `NodeTraits.kt`
- `ParamSchema.kt`
- `PortSchema.kt`
- `BindContext.kt`  
**Спецификация:** `.sdd/specs/pipeline-spi/overview.md#25-спецификация-узла-nodespec`  
**Контракт:** `.sdd/contracts/pipeline-compiler__spi.md#4-контракт-спецификации-и-каталога-узлов-nodespec-noderegistry`  

### Сигнатура (НЕ МЕНЯТЬ):
```kotlin
package com.example.npc.pipeline.nodes.api.spec

import com.example.npc.pipeline.nodes.api.executor.NodeExecutor
import com.example.npc.pipeline.nodes.api.frame.Bank

enum class NodeCategory {
    CONDITION,
    TRANSFORM,
    ACTION
}

data class NodeTraits(
    val isPure: Boolean = true,
    val isDeterministic: Boolean = true,
    val costScore: Int = 1
)

data class PortDef(
    val name: String,
    val bank: Bank,
    val isRequired: Boolean = true,
    val failureDefaultLong: Long = 0L,
    val failureDefaultDouble: Double = 0.0,
    val failureDefaultRef: Any? = null
)

class PortSchema(
    val inputs: List<PortDef> = emptyList(),
    val outputs: List<PortDef> = emptyList(),
    val branches: List<String> = emptyList()
)

data class ParamDef<T>(
    val name: String,
    val defaultValue: T? = null,
    val isRequired: Boolean = true
)

class ParamSchema(val params: List<ParamDef<*>> = emptyList()) {
    constructor(vararg defs: ParamDef<*>) : this(defs.toList())
}

interface BindContext {
    fun getParam(name: String): Any?
    fun getInputSlot(portName: String): Int
    fun getOutputSlot(portName: String): Int
    fun getBank(portName: String): Bank
    fun allocateScratchSlot(): Int
}

interface NodeSpec {
    val id: String
    val category: NodeCategory
    val traits: NodeTraits
    val paramSchema: ParamSchema
    val portSchema: PortSchema

    /**
     * Вызывается компилятором во время фазы Lowering.
     * Связывает логические порты и параметры со статическими слотами FrameLayout.
     */
    fun bind(context: BindContext): NodeExecutor
}
```

### Поведение:
1. `NodeSpec`: объявляет метаданные узла, схему конфигурации (`paramSchema`), контракт входных/выходных портов (`portSchema`), категорию (`NodeCategory`) и свойства (`NodeTraits`).
2. `NodeTraits`:
   - `isPure`: узел детерминирован и не имеет побочных эффектов (кандидат на Constant Folding).
   - `isDeterministic`: результат зависит только от входных регистров.
   - `costScore`: оценка вычислительной сложности (1 = тривиальная проверка, 10 = тяжелый regex).
3. `PortSchema`:
   - `inputs`: список входных портов с указанием ожидаемого банка (`Bank`) и признака обязательности.
   - `outputs`: список выходных портов с дефолтными значениями (`failureDefault*`) для локализации сбоев.
   - `branches`: список именованных переходов ветвления (например, `"then"`, `"else"`).
4. `bind(context)`:
   - Вызывается компилятором ровно один раз во время фазы Lowering.
   - Запрашивает через `BindContext` конкретные индексы слотов памяти и создает иммутабельный экземпляр `NodeExecutor`.
   - Вся тяжелая инициализация (прекомпиляция паттернов, разбор конфига) происходит внутри `bind()`.

### Ошибки:
- При попытке запросить неизвестный параметр в `getParam()` или неизвестный порт в `getInputSlot()`/`getOutputSlot()` выбрасывать `IllegalArgumentException`.

### Граничные случаи:
- Узлы без параметров (`paramSchema = ParamSchema()`): валидно.
- Узлы без выходов (Actions): `portSchema.outputs = emptyList()`.
- Узлы без ветвлений (линейные трансформации): `portSchema.branches = emptyList()`.

### Запрещено:
- Использовать Android SDK (`android.*`).
- Вызывать `bind()` во время исполнения события на горячем пути (разрешено только при компиляции).
- Возвращать разные экземпляры `NodeExecutor` с мутируемым внутренним состоянием.

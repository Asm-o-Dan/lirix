## Задача SPI-P2-004: Реализовать упакованный StepResult

**Модуль:** `:pipeline:nodes-api`  
**Целевой файл:** `pipeline/nodes-api/src/main/kotlin/com/example/npc/pipeline/nodes/api/executor/StepResult.kt`  
**Спецификация:** `.sdd/specs/pipeline-spi/overview.md#22-результат-шага-stepresult-inlined-value-class`  
**Контракт:** `.sdd/contracts/pipeline-compiler__spi.md#3-контракты-исполнения-stepresult-nodeexecutor-effectbuffer`  

### Сигнатура (НЕ МЕНЯТЬ):
```kotlin
package com.example.npc.pipeline.nodes.api.executor

/**
 * Безаллокационный упакованный результат выполнения узла (64-битный Long).
 * - Старшие 32 бита: код операции [op] (NEXT, JUMP, HALT, FAIL).
 * - Младшие 32 бита: целочисленный аргумент [arg] (targetPc, reason, errorCode).
 */
@JvmInline
value class StepResult private constructor(val bits: Long) {
    val op: Int get() = (bits ushr 32).toInt()
    val arg: Int get() = bits.toInt()

    val isNext: Boolean get() = op == OP_NEXT
    val isJump: Boolean get() = op == OP_JUMP
    val isHalt: Boolean get() = op == OP_HALT
    val isFail: Boolean get() = op == OP_FAIL

    companion object {
        const val OP_NEXT: Int = 0
        const val OP_JUMP: Int = 1
        const val OP_HALT: Int = 2
        const val OP_FAIL: Int = 3

        val NEXT: StepResult = StepResult(OP_NEXT.toLong() shl 32)

        fun jump(targetPc: Int): StepResult =
            StepResult((OP_JUMP.toLong() shl 32) or (targetPc.toLong() and 0xFFFF_FFFFL))

        fun halt(reason: Int = 0): StepResult =
            StepResult((OP_HALT.toLong() shl 32) or (reason.toLong() and 0xFFFF_FFFFL))

        fun fail(errorCode: Int): StepResult =
            StepResult((OP_FAIL.toLong() shl 32) or (errorCode.toLong() and 0xFFFF_FFFFL))
    }
}
```

### Поведение:
1. `StepResult` упаковывается в 64-битный регистр процессора (`bits: Long`), не вызывая аллокаций в Java Heap при возврате из не-nullable методов.
2. `op`: старшие 32 бита определяют операцию управления для горячего цикла:
   - `OP_NEXT (0)`: переход к следующему шагу программы (`pc + 1`).
   - `OP_JUMP (1)`: переход по заданному в `arg` программному счетчику (`pc = targetPc`).
   - `OP_HALT (2)`: штатная ранняя терминация конвейера (Early Exit, например подавление спама).
   - `OP_FAIL (3)`: сбой узла с кодом ошибки `errorCode` для применения политики сбоев (FailurePolicy).
3. `arg`: младшие 32 бита хранят целевой PC, код причины остановки или код ошибки.

### Ошибки:
- При вызове `jump(targetPc)` значение `targetPc` должно быть неотрицательным (`targetPc >= 0`).

### Граничные случаи:
- `targetPc = 0`: переход на начало программы (`op = 1, arg = 0`).
- Отрицательные аргументы `errorCode`: корректно упаковываются и распаковываются через 32-битную маску без потери знака.
- `arg = 0` для `halt()`: дефолтная успешная терминация.

### Запрещено:
- Использовать nullable `StepResult?` (вызывает боксинг value class).
- Использовать `StepResult` в дженериках (`List<StepResult>`) на горячем пути.
- Использовать Android SDK (`android.*`).

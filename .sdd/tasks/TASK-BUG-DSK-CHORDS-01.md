# TASK-BUG-DSK-CHORDS-01: Устойчивый поиск аккордов в Desktop (AmDm & MyChords)

## Статус
`DONE`

## 1. Контекст проблемы
Пользователь обратил внимание на баг: при воспроизведении трека группы **«Бригадный подряд» — «Трупы»** (`https://412.amdm.ru/akkordi/brigadnyy_podryad/207027/trupy/`) на десктопе в Lirix отображается:
> «Аккорды не найдены. В базах AmDm и MyChords нет гармонии для этого трека».

При этом на Android-телефоне аккорды для этого же трека успешно находятся.

## 2. Root Cause Analysis (Причина расхождения)

### 2.1. Метаданные из Яндекс Музыки (Windows GSMTC vs Android MediaSession)
- **На Android**: Яндекс Музыка передаёт `artist = "Бригадный подряд"`, `title = "Трупы"`. В AmDm шёл прямой запрос `Бригадный подряд Трупы`, возвращавший точное совпадение.
- **На Windows**: Десктопный клиент Яндекс Музыки отдал в системный GSMTC заголовок `title = "Трупы"`, а в поле артиста передал `artist = "Батарея"` (по имени альбома/сингла «Батарея»).

### 2.2. Архитектурный дефект парсера десктопа (`DesktopLyricsService.kt:335`)
1. Формируется запрос `query = "$artist $title" = "Батарея Трупы"`.
2. По запросу `https://amdm.ru/search/?q=Батарея+Трупы` на сайте AmDm нет результатов, таблица `<table class="items">` отсутствует.
3. Десктопный код использует незащищённую регулярку:
   ```kotlin
   val songUrl = Regex("""<a\s+[^>]*href=["']((?:https?://[^/]*amdm\.ru)?/akkordi/[^"']+)["']""").find(amdmHtml)?.groupValues?.get(1)
   ```
4. Поскольку таблицы результатов поиска нет, регулярка захватывает **первую попавшуюся ссылку на странице**, содержащую `/akkordi/` — а именно ссылку на популярные аккорды в шапке/навигации сайта:
   `https://amdm.ru/akkordi/popular/`!
5. Десктоп делает GET-запрос каталога `popular/`, передаёт его в `AmDmChordParser.parseAmDmHtml(pageHtml)`. Парсер, не находя блока `<pre itemprop="chordsBlock">`, возвращает `null`.
6. Запрос в MyChords для `Батарея Трупы` также возвращает пустоту.

## 3. Требования к реализации (DoD)

В `desktop/src/main/kotlin/com/lirix/app/desktop/lyrics/DesktopLyricsService.kt`:

1. **Строгая изоляция таблицы результатов (`<table class="items">`)**:
   - Никогда не парсить ссылки на песни вне `<table[^>]*class=["'][^"']*items[^"']*["'][^>]*>(.*?)</table>`. Если таблицы нет — считать результат поиска нулевым.
2. **Fallback-поиск по названию трека (`title`)**:
   - Если первичный поиск по `"$artist $title"` не вернул таблицы или не нашёл совпадений, выполнить вторичный fallback-запрос только по `"$title"` (например, `https://amdm.ru/search/?q=Трупы`).
   - При поиске по чистому названию AmDm находит список песен, где первой строкой идёт `Бригадный подряд — Трупы` (`/akkordi/brigadnyi_podryad/207027/trupy/`).
3. **Фильтрация и сопоставление кандидатов**:
   - Извлечь из строки таблицы название песни и имя исполнителя.
   - Проверить токенизацию: если название трека совпадает с `title` (или `artist` встречается в строке), выбрать данный URL.
4. **Аналогичный fallback для MyChords**:
   - Если автокомплит по `$artist $title` пуст, повторить автокомплит по `$title`.
5. **Сохранение в локальный дисковый кэш**:
   - При успешном обнаружении аккорды сохраняются в `.lirix_cache/<trackKey>.cache` и отдаются в `DesktopLyricsState.chords`.

## 4. Проверка и тесты
1. Запуск десктопа или вызов `fetchChords("Батарея", "Трупы")` должен возвращать аккорды трека «Бригадный подряд — Трупы» из базы AmDm.
2. Проверка сборки: `./gradlew :desktop:compileKotlin` проходит без ошибок.

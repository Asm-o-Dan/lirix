## Задача SPI-P2-012: Реализовать встроенные исполнители действий

**Модуль:** `:pipeline:nodes-builtin`  
**Целевые файлы:** `pipeline/nodes-builtin/src/main/kotlin/com/example/npc/pipeline/nodes/builtin/action/`  
- `SetCategoryActionExecutor.kt`
- `CreateTransactionActionExecutor.kt`
- `SaveToStorageActionExecutor.kt`
- `DropEventActionExecutor.kt`
- `StopProcessingActionExecutor.kt`  
**Спецификация:** `.sdd/specs/pipeline-spi/overview.md#33-действия-actions`  
**Контракт:** `.sdd/contracts/pipeline-compiler__spi.md#3-контракты-исполнения-stepresult-nodeexecutor-effectbuffer`  

### Сигнатура (НЕ МЕНЯТЬ):
```kotlin
package com.example.npc.pipeline.nodes.builtin.action

import com.example.npc.pipeline.nodes.api.effect.EffectBuffer
import com.example.npc.pipeline.nodes.api.executor.NodeExecutor
import com.example.npc.pipeline.nodes.api.executor.StepResult
import com.example.npc.pipeline.nodes.api.frame.Frame

class SetCategoryActionExecutor(
    val categoryOrdinal: Long,
    val confidenceBits: Long,
    val engineOrdinal: Long,
    val effectCode: Int,
    val nextPc: Int
) : NodeExecutor {
    override fun execute(frame: Frame, buffer: EffectBuffer): StepResult
}

class CreateTransactionActionExecutor(
    val inAmountMinorSlot: Int,
    val inCurrencyOrdinalSlot: Int,
    val inTxRefSlot: Int,
    val directionOrdinal: Long,
    val statusOrdinal: Long,
    val effectCode: Int,
    val nextPc: Int
) : NodeExecutor {
    override fun execute(frame: Frame, buffer: EffectBuffer): StepResult
}

class SaveToStorageActionExecutor(
    val completeProcessing: Boolean,
    val effectCode: Int,
    val nextPc: Int
) : NodeExecutor {
    override fun execute(frame: Frame, buffer: EffectBuffer): StepResult
}

class DropEventActionExecutor(
    val reasonCode: Int,
    val effectCode: Int
) : NodeExecutor {
    override fun execute(frame: Frame, buffer: EffectBuffer): StepResult
}

class StopProcessingActionExecutor(
    val reasonCode: Int
) : NodeExecutor {
    override fun execute(frame: Frame, buffer: EffectBuffer): StepResult
}
```

### Поведение:
1. `SetCategoryActionExecutor`:
   - Вызывает `buffer.begin(effectCode)`.
   - Записывает `categoryOrdinal`, `confidenceBits` и `engineOrdinal` через `buffer.putLong()`.
   - Завершает запись `buffer.end()` и возвращает `StepResult.NEXT` (или `jump(nextPc)`).
2. `CreateTransactionActionExecutor`:
   - Считывает сумму из `frame.longs[inAmountMinorSlot]`, валюту из `frame.longs[inCurrencyOrdinalSlot]`, объект DTO из `frame.refs[inTxRefSlot]`.
   - Буферизует эффект: `buffer.begin(effectCode)`, `putLong(amount)`, `putLong(currency)`, `putLong(directionOrdinal)`, `putLong(statusOrdinal)`, `putRef(txRef)`, `buffer.end()`.
   - Возвращает `StepResult.NEXT`.
3. `SaveToStorageActionExecutor`:
   - Буферизует маркер сохранения в Room: `buffer.begin(effectCode)`, `putLong(if (completeProcessing) 1L else 0L)`, `buffer.end()`.
   - Возвращает `StepResult.NEXT`.
4. `DropEventActionExecutor`:
   - Буферизует аудит подавления спама: `buffer.begin(effectCode)`, `putLong(reasonCode.toLong())`, `buffer.end()`.
   - Немедленно останавливает конвейер, возвращая `StepResult.halt(reasonCode)`.
5. `StopProcessingActionExecutor`:
   - Прекращает исполнение конвейера без фиксации дропа, возвращая `StepResult.halt(reasonCode)`.

### Ошибки:
- Если буфер эффектов переполнен (`buffer.begin()` возвращает `false`), узел не падает, а фиксирует сбой в диагностике рантайма и возвращает `StepResult.fail(ERR_EFFECT_REJECTED)`.

### Граничные случаи:
- Несколько действий `SetCategory`: буферизуются последовательно, на фазе коммита применяется политика `LAST_WINS`.
- `DropEvent`: следующие за ним шаги конвейера не выполняются (сигнал `HALT`).

### Запрещено:
- Использовать Android SDK (`android.*`).
- Вызывать методы базы данных Room DAO, репозиториев или сети напрямую внутри `execute()`.
- Аллоцировать DTO-объекты на горячем пути.

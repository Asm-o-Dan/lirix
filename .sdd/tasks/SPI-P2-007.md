## Задача SPI-P2-007: Реализовать интерфейс NodeExecutor

**Модуль:** `:pipeline:nodes-api`  
**Целевой файл:** `pipeline/nodes-api/src/main/kotlin/com/example/npc/pipeline/nodes/api/executor/NodeExecutor.kt`  
**Спецификация:** `.sdd/specs/pipeline-spi/overview.md#23-исполнитель-узла-nodeexecutor`  
**Контракт:** `.sdd/contracts/pipeline-compiler__spi.md#3-контракты-исполнения-stepresult-nodeexecutor-effectbuffer`  

### Сигнатура (НЕ МЕНЯТЬ):
```kotlin
package com.example.npc.pipeline.nodes.api.executor

import com.example.npc.pipeline.nodes.api.effect.EffectBuffer
import com.example.npc.pipeline.nodes.api.frame.Frame

/**
 * Исполняемый контракт скомпилированного узла на горячем пути.
 * Экземпляры NodeExecutor иммутабельны, потокобезопасны и могут переиспользоваться
 * множеством параллельных рабочих потоков.
 */
fun interface NodeExecutor {
    /**
     * Выполняет обработку события над регистровым фреймом.
     *
     * @param frame Рабочий регистровый фрейм текущего потока.
     * @param buffer Предвыделенный буфер для постановки побочных эффектов.
     * @return [StepResult] с инструкцией для диспетчера рантайма.
     */
    fun execute(frame: Frame, buffer: EffectBuffer): StepResult
}
```

### Поведение:
1. Представляет собой функциональный интерфейс (SAM), исполняемый в горячем цикле конвейера.
2. Принимает поток-локальный `Frame` и рабочий `EffectBuffer`.
3. Считывает данные из входных слотов массивов `frame.longs`, `frame.doubles`, `frame.refs`, `frame.texts` по разрешенным статическим индексам.
4. Записывает результаты вычислений в выходные слоты соответствующих массивов.
5. При необходимости эмиссии побочных эффектов вызывает методы `buffer.begin(kindCode)`, `buffer.put*()` и `buffer.end()`.
6. Возвращает упакованный `StepResult` (`NEXT`, `jump(targetPc)`, `halt(reason)` или `fail(errorCode)`).
7. Обязан исполняться строго за $O(1)$ или $O(n)$ от длины входного текста с бюджетом не более 15 микросекунд.

### Ошибки:
- Исключения в `execute` не должны просачиваться наружу необработанными. При возникновении внутренней ошибки узел либо возвращает `StepResult.fail(code)`, либо исключение ловится раннером рантайма с откатом эффектов.

### Граничные случаи:
- Пустые строки в текстовых регистрах: должны корректно обрабатываться без `NullPointerException` или `IndexOutOfBoundsException`.
- Запись в буфер эффектов при его переполнении: проверяется возвращаемое значение `buffer.begin()` / `put*()`.

### Запрещено:
- Использовать Android SDK (`android.*`).
- Аллоцировать любые объекты в Heap внутри метода `execute()`.
- Использовать Java/Kotlin Reflection или динамический вызов методов.
- Хранить мутабельное состояние внутри полей экземпляра `NodeExecutor` (экземпляр разделяется между параллельными потоками).
- Выполнять блокирующий ввод-вывод (сеть, диск, базы данных, IPC).

### Критерии приёмки (DoD):
- [ ] Интерфейс `NodeExecutor` скомпилирован в модуле `:pipeline:nodes-api`.
- [ ] Unit-тест с фиктивным безаллокационным исполнителем (`NodeExecutorTest.kt`).
- [ ] Инвариант потокобезопасности: параллельное исполнение одного экземпляра `NodeExecutor` в N потоках с разными экземплярами `Frame` дает детерминированный результат без гонок.

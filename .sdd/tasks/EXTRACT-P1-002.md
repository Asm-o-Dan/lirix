## Задача EXTRACT-P1-002: Реализовать рукописный O(n) парсер сумм AmountParser

**Модуль:** `:extract:finance`  
**Целевой файл:** `extract/finance/src/main/kotlin/com/example/npc/extract/finance/AmountParser.kt`  
**Спецификация:** `.sdd/specs/extract-finance/overview.md#42-линейный-on-парсер-сумм-amountparser`  
**Архитектура:** `.sdd/architecture_phase1.md#34`  

### Входные контракты / сигнатуры:
```kotlin
package com.example.npc.extract.finance

object AmountParser {
    /**
     * Преобразует строковое представление суммы в неделимые минорные единицы (Long, копейки/центы).
     * Работает без регулярных выражений за O(n) линейный проход.
     *
     * Поддерживаемые форматы:
     * - "120.50" -> 12050L
     * - "1 250,00" -> 125000L
     * - "4.40" -> 440L
     * - "500" -> 50000L
     *
     * @return сумма в копейках/центах или null при невозможности парсинга.
     */
    fun parseToMinor(rawAmount: String): Long?
}
```

### Инварианты и алгоритм:
1. Запрет регулярных выражений: парсинг осуществляется посимвольным сканированием строки.
2. Игнорирование пробелов-разделителей тысяч (`"1 250.00"` $\to$ `"1250.00"`).
3. Поддержка обоих разделителей копеек: точка `.` и запятая `,`.
4. Нормализация дробной части:
   - Отсутствует дробная часть (`"500"`) $\to$ `* 100L`.
   - 1 знак (`"500.5"`) $\to$ трактуется как 50 копеек (`50050L`).
   - 2 знака (`"500.55"`) $\to$ `50055L`.
   - Больше 2 знаков $\to$ отбрасывание или округление без переполнения.
5. Защита от переполнения: валидация `Math.addExact` / `Math.multiplyExact`.
6. Отрицательные числа или некорректные символы приводят к возврату `null`.

### Критерии приемки (DoD):
- [ ] Никаких вычислений с `Double`/`Float` (исключение погрешностей округления).
- [ ] Отработка 1000 парсингов за < 5 мс на JVM.
- [ ] Покрытие всеми тестовыми случаями из телеметрии Poco M7 (`4.40`, `150.00`, `1 200,50`).

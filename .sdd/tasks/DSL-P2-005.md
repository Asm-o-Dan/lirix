## Задача DSL-P2-005: Реализовать StageDefinition

**Файл:** `pipeline/dsl/src/main/kotlin/com/example/npc/pipeline/dsl/StageDefinition.kt` (создать)  
**Модуль:** `:pipeline:dsl` (чистый Kotlin JVM)  
**Спека:** `.sdd/specs/pipeline-dsl/overview.md#3-схема-этапа-stagedefinition-линейный-шаг-конвейера`  
**Контракт:** `.sdd/contracts/pipeline-dsl__compiler.md#2-модели-схемы-dsl-pipelinedefinition-stagedefinition`  

**Сигнатура (НЕ МЕНЯТЬ):**
```kotlin
package com.example.npc.pipeline.dsl

import kotlinx.serialization.SerialName
import kotlinx.serialization.Serializable

@Serializable
data class StageDefinition(
    @SerialName("id")
    val id: String,

    @SerialName("name")
    val name: String,

    @SerialName("enabled")
    val enabled: Boolean = true,

    @SerialName("condition")
    val condition: ConditionDefinition? = null,

    @SerialName("transforms")
    val transforms: List<TransformDefinition> = emptyList(),

    @SerialName("actions")
    val actions: List<ActionDefinition> = emptyList(),

    @SerialName("terminateOnMatch")
    val terminateOnMatch: Boolean = false
) {
    init {
        require(id.matches(PipelineDefinition.ID_REGEX)) {
            "Stage ID '$id' is invalid. Must match pattern ^[a-z0-9_-]{3,64}$"
        }
        require(name.isNotBlank() && name.length <= PipelineDefinition.MAX_NAME_LENGTH) {
            "Stage name must be between 1 and ${PipelineDefinition.MAX_NAME_LENGTH} characters, but was: '$name'"
        }
        require(transforms.isNotEmpty() || actions.isNotEmpty()) {
            "Stage '$id' must declare at least one transform or action"
        }
    }
}
```

**Поведение:**
1. Представляет декларативное описание одного линейного шага (этапа) конвейера обработки событий.
2. Поддерживает сериализацию в JSON с явными `@SerialName` для всех полей.
3. Проверяет корректность идентификатора `id` по регулярному выражению `^[a-z0-9_-]{3,64}$`.
4. Проверяет, что имя `name` не пустое и не превышает 128 символов.
5. Гарантирует наличие полезной нагрузки: этап обязан содержать хотя бы одну трансформацию в `transforms` или хотя бы одно действие в `actions`.
6. Поле `condition` служит входным фильтром-гейтом: если `condition == null`, этап исполняется безусловно.
7. Флаг `terminateOnMatch = true` указывает компилятору и рантайму, что при успешном исполнении этапа обработка конвейера должна быть завершена (Early Exit).

**Ошибки:**
- `IllegalArgumentException`: если `id` не соответствует маске `^[a-z0-9_-]{3,64}$`.
- `IllegalArgumentException`: если `name` пустое, состоит только из пробелов или длиннее 128 символов.
- `IllegalArgumentException`: если одновременно `transforms.isEmpty()` и `actions.isEmpty()`.
- `SerializationException`: при ошибках синтаксиса JSON или полиморфной десериализации вложенных узлов.

**Граничные случаи:**
- `id = "abc"` (3 символа) -> валидный минимальный ID.
- `id = "a_b-c_123"` -> валидный ID.
- `id = "ab"` (2 символа) -> выбрасывает `IllegalArgumentException`.
- `id = "stage 1"` (с пробелом) -> выбрасывает `IllegalArgumentException`.
- `name` ровно 128 символов -> валидно.
- `name` 129 символов -> выбрасывает `IllegalArgumentException`.
- `transforms` содержит 1 элемент, `actions` пуст -> валидно.
- `transforms` пуст, `actions` содержит 1 элемент -> валидно.
- И `transforms`, и `actions` пусты -> выбрасывает `IllegalArgumentException`.

**Запрещено:**
- Использовать Android SDK классы.
- Допускать циклические графы переходов (модель строго линейная, ветвление через `terminateOnMatch` и `condition`).
- Использовать изменяемые коллекции (`MutableList`).

**Критерий приёмки:**
- Файл скомпилирован в модуле `:pipeline:dsl`.
- Юнит-тесты проверяют все условия валидации `init`, граничные длины `id` и `name`, а также round-trip сериализацию `StageDefinition`.
